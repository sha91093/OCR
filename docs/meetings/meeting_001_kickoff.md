## 議事内容

### 1. プロジェクト概要説明（田中 司会）

**田中**: 皆さんお集まりいただきありがとうございます。今日はOCRツール開発のキックオフ会議です。
クライアントの要件を整理しましょう。主な要件は以下の通りです：

**要件サマリー**：
- ndlocr-liteを活用したOCRツールの開発
- 申請書等の読み取りに使用
- 申請書の様式を登録可能（PDFや画像内の読み取り箇所を複数指定し、CSVに出力）
- 複数ページの読み取りに対応
- 低スペックのPCでも稼働可能

---

### 2. 技術調査・アーキテクチャ検討（渡辺 アーキテクト）

**渡辺**: ndlocr-liteについて確認します。NDLOCRは国立国会図書館が開発した日本語OCRエンジンで、
ndlocr-liteはその軽量版です。Pythonベースで動作します。

**技術スタック提案**：

```
【バックエンド】
- Python 3.9+
- ndlocr-lite（OCRエンジン）
- pdf2image（PDF→画像変換）
- Pillow（画像処理）
- OpenCV（画像前処理）
- FastAPI（APIサーバー）
- SQLite（設定・様式データ保存）

【フロントエンド】
- Tkinter（デスクトップGUI）※低スペックPC対応のためWebブラウザ不要
  または
- PyQt5/PySide6（より高機能なGUI）

【データ出力】
- csv（標準ライブラリ）
- openpyxl（Excel出力オプション）
```

**田中**: 低スペックPC対応という観点から、Webベースではなくデスクトップアプリのほうがいいですね。

**渡辺**: そうですね。Tkinterは標準ライブラリなので追加インストールが最小限。
ただし、UIの自由度を考えるとPySide6も選択肢に入ります。

---

### 3. 機能要件の詳細化（佐藤 バックエンド）

**佐藤**: OCR処理の観点から機能を整理します。

**コア機能リスト**：
1. **様式管理機能**
   - 様式（フォーム）の新規登録・編集・削除
   - PDF/画像ファイルのアップロード・プレビュー
   - 読み取り領域の矩形選択・ラベル付け
   - 複数読み取り領域の定義（フィールドセット）

2. **OCR処理機能**
   - ndlocr-liteによる日本語テキスト認識
   - 複数ページ対応（PDFの全ページ処理）
   - バッチ処理（複数ファイルの一括処理）
   - 処理結果のプレビュー・修正

3. **CSV出力機能**
   - 定義フィールドへの認識結果マッピング
   - ヘッダー行の自動生成
   - 文字コード指定（UTF-8/Shift-JIS）
   - 複数ファイルの結果を1つのCSVに集約

---

### 4. UI/UX設計（木村 フロントエンド）

**木村**: ユーザーが申請書を処理する流れを想定してUIを設計します。

**主要画面構成**：

```
┌─────────────────────────────────────────┐
│  OCR申請書読み取りツール                 │
├─────────┬───────────────────────────────┤
│ メニュー │ メインコンテンツエリア         │
│         │                               │
│ ・様式管理│  [様式管理画面]               │
│ ・OCR処理│  - 様式一覧                   │
│ ・設定  │  - 領域定義エディタ            │
│         │                               │
│         │  [OCR処理画面]                │
│         │  - ファイル選択               │
│         │  - 処理実行                   │
│         │  - 結果確認・CSV出力          │
└─────────┴───────────────────────────────┘
```

**木村**: 低スペックPC向けにTkinterを採用し、画像プレビューと矩形選択機能を
Pillowで実装します。

---

### 5. テスト戦略（中村 QA）

**中村**: 品質を確保するためのテスト計画です。

**テスト種別**：
- **単体テスト**: OCRエンジン連携、座標変換、CSV出力
- **統合テスト**: 様式登録→OCR処理→CSV出力の一連フロー
- **性能テスト**: 低スペックPCでの動作確認（CPU: Intel Celeron相当, RAM: 4GB想定）
- **回帰テスト**: 各機能の変更後の動作確認

## 決定事項

1. **技術スタック確定**
   - バックエンド: Python 3.9+, ndlocr-lite, pdf2image, Pillow, OpenCV
   - GUI: Tkinter（標準ライブラリ、低スペック対応）
   - DB: SQLite（軽量、インストール不要）
   - 出力: CSV（UTF-8/Shift-JIS対応）

2. **アーキテクチャ**: MVC パターン採用
   - Model: OCR処理・データ管理
   - View: Tkinter GUI
   - Controller: ビジネスロジック

3. **ファイル構成**:
   ```
   OCR/
   ├── main.py              # エントリーポイント
   ├── src/
   │   ├── core/            # OCRコア処理
   │   ├── ui/              # GUI画面
   │   └── utils/           # ユーティリティ
   ├── templates/           # 様式テンプレートDB
   ├── config/              # 設定ファイル
   ├── tests/               # テストコード
   └── docs/                # ドキュメント
   ```
